Guía de scripting

Cómo construir un script de performance sobre RelampoTickets: flujo paso a paso, think times, assertions y correlación de los 18 valores dinámicos.

Los flujos y las grabaciones pueden cambiar; los principios de esta guía no.

Recorrido

El flujo base

Estas 13 acciones capturan prácticamente todos los valores dinámicos de la aplicación. Cada paso indica qué hace el usuario, qué requests genera, cuánto esperar y qué validar.

Think time

Es el tiempo que una persona real tarda en leer, decidir o escribir. Va después de recibir la respuesta y antes de la siguiente acción. Sin think times, el script no simula usuarios: simula una inundación.

Caso especial

El valor encriptado: relampo_token

El problema

Respuesta de POST /api/reservations
  "relampoToken": "9788897b868175dc…"       ← valor A (64 caracteres)

Request de POST /pay/start
  relampo_token=4b5254595549584f…           ← valor B (128 caracteres)

A ≠ B. El valor B no aparece en ninguna respuesta: lo calcula el JavaScript del navegador antes de enviar el formulario. Si se correlaciona A y se reenvía tal cual, el servidor responde 403 you sent the RAW relampo_token (value A).

Ningún correlador automático puede resolver esto. Hay que escribir código.

El método

Por cada carácter de A: se toma su código numérico, se mezcla con XOR contra el código del carácter que le toca de la sal, y el resultado se escribe en hexadecimal de dos dígitos.

La sal es relampo-public-salt-v1 — pública, está en /static/app.js. Cuando se termina (22 caracteres) vuelve a empezar. Como cada carácter produce 2 dígitos, B siempre mide el doble que A.

Carácter de ACarácter de la salXOREn hex
9 (57)r (114)754b
7 (55)e (101)8252

→ B empieza con 4b52…

Relampo — bloque spark en POST /pay/start

// PASO 1 — Leer el token que extrajimos en el request anterior
var tokenA = vars.get("relampo_token_a");

// PASO 2 — Transformarlo (misma lógica que app.js en el navegador)
var salt = "relampo-public-salt-v1";
var tokenB = "";

for (var i = 0; i < tokenA.length; i++) {
  var x = tokenA.charCodeAt(i) ^ salt.charCodeAt(i % salt.length);
  tokenB = tokenB + (x < 16 ? "0" : "") + x.toString(16);
}

// PASO 3 — Guardarlo para usarlo en el body como {{relampo_token_b}}
vars.set("relampo_token_b", tokenB);

JMeter — JSR223 PreProcessor (Groovy)

def tokenA = vars.get("relampo_token_a")
def salt = "relampo-public-salt-v1"
def tokenB = new StringBuilder()

for (int i = 0; i < tokenA.length(); i++) {
    int x = ((int) tokenA.charAt(i)) ^ ((int) salt.charAt(i % salt.length()))
    tokenB.append(String.format("%02x", x))
}

vars.put("relampo_token_b", tokenB.toString())

k6 — función JavaScript

function signRelampoToken(tokenA) {
  const salt = "relampo-public-salt-v1";
  let tokenB = "";
  for (let i = 0; i < tokenA.length; i++) {
    const x = tokenA.charCodeAt(i) ^ salt.charCodeAt(i % salt.length);
    tokenB += x.toString(16).padStart(2, "0");
  }
  return tokenB;
}

const tokenA = res.json().relampoToken;
const tokenB = signRelampoToken(tokenA);

Gatling — función Scala

def signRelampoToken(tokenA: String): String = {
  val salt = "relampo-public-salt-v1"
  val sb = new StringBuilder
  for (i <- tokenA.indices) {
    val x = tokenA(i) ^ salt(i % salt.length)
    sb.append(f"$x%02x")
  }
  sb.toString
}

.exec(session => session.set("tokenB", signRelampoToken(session("tokenA").as[String])))

Cómo verificar que lo hiciste bien

  1. El valor B mide exactamente el doble que A: 128 contra 64 caracteres.
  2. El POST /pay/start responde 302 con Location: /pay/authorize?state=…
  3. Ejecutar dos iteraciones seguidas: si la segunda también pasa, la transformación está bien. El token es de un solo uso, así que un valor grabado fallaría.
Modo avanzado

Si la app corre con RELAMPO_TOKEN_MODE=hmac, la transformación pasa a ser B = hex(HMAC-SHA256(A, salt)). En k6: crypto.hmac('sha256', salt, tokenA, 'hex'). En JMeter: javax.crypto.Mac con HmacSHA256.

Validación

Assertions

Un script sin assertions miente: reporta éxito aunque el servidor esté devolviendo errores.

Tipo de requestValidá siempreValidá además
Página HTMLStatus 200Un texto que solo aparece si la página cargó bien, y el input oculto que se va a extraer
API JSONStatus 200 / 201Que exista el campo que se va a correlacionar
RedirectStatus 302Que el Location contenga el parámetro que se va a extraer
Confirmación finalStatus 200"status":"CONFIRMED" en el ticket
Assertion negativa recomendada

En todos los requests: que el body no contenga correlationError. Si aparece, algún valor se correlacionó mal y el script está “pasando” sobre un flujo roto.

Realismo

Think times y perfil de carga

Conviene aplicar una variación de ±30 % para que los usuarios virtuales no queden sincronizados.

MomentoTiempo
Leer una página3–8 s
Llenar un formulario corto (login)10–15 s
Llenar un formulario largo (crear evento)15–25 s
Elegir de una lista5–8 s
Entre requests automáticos (redirects, fetch de la misma página)0 s
Entre reservar y pagarmáximo 60 s

Con el límite de 5 sesiones por nodo, una prueba razonable es 5 VUs por nodo, rampa de 30 s y 10–15 minutos de duración. Con la ejecución distribuida de Relampo en 4 nodos, se llega a 20 VUs.

Cierre

Checklist antes de dar el script por terminado

  • Corre dos iteraciones seguidas sin errores — la prueba real de la correlación
  • Ningún valor dinámico quedó escrito a mano: buscar EV-, CAT-, TCK-, RES-, PUB- en el script
  • El csrf_token del paso 1 llega hasta el paso 12
  • El relampo_token se transforma con el preprocesador, no se envía crudo
  • Los redirects del pago están con “seguir redirects” desactivado donde hace falta
  • Hay assertions en todos los pasos, incluida "status":"CONFIRMED" al final
  • Hay think times entre las acciones del usuario
  • Usuario y datos están parametrizados por CSV, no hardcodeados
  • El flujo termina en /logout
  • Se quitó el header X-Practice-Hints de la versión final

Práctica

Ejercicios por nivel

1 · Básico — login y navegar

Resolver relampo_session, csrf_token y bearer.

2 · Intermedio — crear y editar

publish_token de un solo uso, event_id y event_rev con If-Match (428 y 412).

3 · Avanzado — comprar

catalog_id en JSON escapado, X-Correlation-Id, state y code de los redirects, view_state.

4 · Experto — pago completo

relampo_token con preprocesador, más las reglas de un solo uso y los 60 segundos.

5 · Maestro — prueba real

Todo lo anterior con datos parametrizados, ocurrencias aleatorias, think times variables y assertions completas.
